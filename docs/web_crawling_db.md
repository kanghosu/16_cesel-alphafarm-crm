# 웹크롤링DB 운영 원칙

## 핵심 원칙

`12_웹크롤링DB`는 후보 저장소입니다. 웹 검색, Naver Place, Google, Instagram, DART, KOTRA, 리서치 브리프에서 찾은 업체는 이 탭에 먼저 넣습니다.

`01_고객DB`는 진짜 고객 관리 탭입니다. 아래 중 하나가 확인된 경우에만 올라갑니다.

- 회신이 왔음
- 오프라인에서 만났음
- 연락처를 직접 받았음
- 담당자 또는 담당 부서가 확인됐음

즉, 점수가 A여도 웹에서 긁은 미검증 후보는 고객DB가 아닙니다.

## 추천 흐름

1. `CESeL CRM > 웹크롤링DB 초기화`
2. `12_웹크롤링DB`에 후보 입력
3. `CESeL CRM > 웹리드 점수화`
4. 진짜 접촉할 후보만 `타깃리스트반영 = Y`
5. `CESeL CRM > 선택 웹리드 타깃 반영`
6. 전화/메일/방문 후 `검증상태` 업데이트
7. `CESeL CRM > 검증완료 고객DB 반영`

## 검증상태 기준

- `미검증`: 웹/리서치에서만 발견. 고객DB 승격 불가.
- `검증중`: 공식 채널이나 담당자를 확인 중. 고객DB 승격 불가.
- `연락처확보`: 연락처, 이메일, 담당자명 중 하나를 확보. 고객DB 승격 가능.
- `회신옴`: 메일/전화/DM 답변 확인. 고객DB 승격 가능.
- `오프라인접점`: 방문, 소개, 행사, 미팅 등 실제 접점 확인. 고객DB 승격 가능.
- `담당자확인`: 담당자 또는 담당 부서 확인. 고객DB 승격 가능.
- `부적합`: 관리 대상 제외.

## 첨부 리서치 브리프 활용

`CESeL CRM > 리서치 후보 10개 넣기`는 첨부 리서치 브리프의 우선 후보 10개를 `12_웹크롤링DB`에만 넣습니다. 고객DB에는 넣지 않습니다.

넣은 뒤 `웹리드 점수화`를 실행하면 `고객DB승격가능 = N`으로 표시됩니다. 실제 회신, 오프라인 접점, 연락처 확보가 생긴 뒤에만 고객DB 승격 대상이 됩니다.

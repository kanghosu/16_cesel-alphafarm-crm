# 웹크롤링DB 운영 원칙

## 핵심 원칙

`12_웹크롤링DB`는 후보 저장소입니다. 웹 검색, Naver Place, Google, Instagram, DART, KOTRA, 리서치 브리프에서 찾은 업체는 이 탭에 먼저 넣습니다.

`01_고객DB`는 진짜 고객 관리 탭입니다. 아래 중 하나가 확인된 경우에만 올라갑니다.

- 회신이 왔음
- 오프라인에서 만났음
- 연락처를 직접 받았음
- 담당자 또는 담당 부서가 확인됐음

즉, 점수가 A여도 웹에서 긁은 미검증 후보는 고객DB가 아닙니다.

## 추천 흐름

1. `CESeL CRM > 웹크롤링DB 초기화`
2. `12_웹크롤링DB`에 후보 입력
3. `CESeL CRM > 웹리드 점수화`
4. 진짜 접촉할 후보만 `타깃리스트반영 = Y`
5. `CESeL CRM > 선택 웹리드 타깃 반영`
6. 전화/메일/방문 후 `접촉단계`와 `고객DB승격근거` 업데이트
7. `CESeL CRM > 검증완료 고객DB 반영`

## 접촉단계 기준

- `미접촉`: 아직 아무 접촉도 하지 않음.
- `온라인접수`: 제안 접수폼, 고객센터, 대표메일 등으로 접수.
- `메일발송`: 메일 발송 완료.
- `전화시도`: 전화했으나 담당자 연결 전.
- `방문시도`: 현장 방문 또는 대면 접촉 시도.
- `회신옴`: 답변 확인.
- `미팅예정`: 미팅 일정 잡힘.
- `미팅완료`: 실제 미팅 완료.
- `부적합`: 관리 대상 제외.

## 고객DB승격근거 기준

- `없음`: 고객DB 승격 불가.
- `회신`: 고객이 답변함.
- `오프라인접점`: 방문, 소개, 행사, 미팅 등 실제 접점 확인.
- `연락처확보`: 연락처, 이메일, 담당자명 중 하나를 확보.
- `담당자확인`: 담당자 또는 담당 부서 확인.

`접촉단계`는 진행상태이고, `고객DB승격근거`는 고객DB에 올릴 수 있는 이유입니다. 예를 들어 `접촉단계 = 메일발송`이어도 `고객DB승격근거 = 없음`이면 고객DB로 넘어가지 않습니다.

## 첨부 리서치 브리프 활용

`CESeL CRM > 서울경기 예상수요 넣기`는 첨부 리서치 브리프의 우선 후보를 `12_웹크롤링DB`에만 넣습니다. 고객DB에는 넣지 않습니다.

넣은 뒤 `웹리드 점수화`를 실행하면 `고객DB승격가능 = N`으로 표시됩니다. 실제 회신, 오프라인 접점, 연락처 확보가 생긴 뒤에만 고객DB 승격 대상이 됩니다.

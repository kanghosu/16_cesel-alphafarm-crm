# CESeL AlphaFarm CRM 사용법

## 1. 처음 한 번만 하는 개발자 설정

이 폴더에서 실행합니다.

```powershell
npm install
npm test
npm run gas:login
npm run gas:push
```

`npm run gas:login`은 Google 로그인 창을 엽니다. 반드시 아래 시트를 편집할 수 있는 Google 계정으로 로그인하세요.

```text
https://docs.google.com/spreadsheets/d/1kVbvt5ksr-Kw5T-8FfAOmEYqKRTLyah8Gc4ThvhRBtk/edit
```

기존 구글시트에 붙이려면 `npm run gas:create`를 쓰지 않습니다. 해당 명령은 새 스프레드시트를 만들 수 있습니다.

아래 순서로 기존 시트에 바인딩된 Apps Script 프로젝트 ID를 가져옵니다.

1. 구글시트 상단 메뉴에서 `확장 프로그램 > Apps Script`를 누릅니다.
2. Apps Script 화면이 열리면 왼쪽 톱니바퀴 `프로젝트 설정`을 누릅니다.
3. `스크립트 ID`를 복사합니다. URL의 `/d/`와 `/edit` 사이 값도 script ID입니다.
4. `.clasp.json.example`을 `.clasp.json`으로 복사합니다.
5. `PASTE_APPS_SCRIPT_ID_HERE`를 script ID로 바꿉니다.
6. `npm run gas:push`를 실행합니다.

정리하면 기존 시트 연결은 다음 방식입니다.

```powershell
npm run gas:login
Copy-Item .clasp.json.example .clasp.json
notepad .clasp.json
npm run gas:push
```

`notepad .clasp.json`에서 script ID만 바꿔 저장하면 됩니다.

## 2. 구글시트에서 처음 한 번만 하는 설정

1. 구글시트를 새로고침합니다.
2. 상단 메뉴에 `CESeL CRM`이 생겼는지 확인합니다.
3. `CESeL CRM > 초기 설정`을 누릅니다.
4. 권한 승인 창이 나오면 승인합니다.

초기 설정은 기존 v2 구조를 유지하면서 `08_타깃리스트`와 `01_고객DB`에 리드품질 필드를 추가합니다.

웹에서 찾은 후보를 따로 관리하려면 이어서 `CESeL CRM > 웹크롤링DB 초기화`도 누릅니다. 그러면 `12_웹크롤링DB` 탭이 생깁니다.

## 3. 웹/리서치 후보를 따로 관리하는 순서

웹 검색, Naver Place, Google, Instagram, DART, KOTRA, 첨부 리서치 브리프에서 찾은 후보는 `01_고객DB`에 바로 넣지 않습니다.

먼저 `12_웹크롤링DB`에 넣습니다.

필수로 채우면 좋은 열:

- `제품군`
- `업체명`
- `지역`
- `고객유형`
- `웹출처URL` 또는 `공개 출처`
- `공식 연락채널`
- `시설/자산 단서`
- `예산/투자 단서`
- `의사결정자 단서`
- `접촉단계`
- `고객DB승격근거`

그 다음 아래 메뉴를 씁니다.

```text
CESeL CRM > 웹리드 점수화
```

이때 `고객DB승격가능`이 자동으로 계산됩니다. 기본적으로 웹수집/미검증 후보는 점수가 A여도 `N`입니다.

화면이 너무 넓거나 판단열이 안 보이면 아래 메뉴를 누릅니다.

```text
CESeL CRM > 웹DB 시인성 개선
```

그러면 왼쪽부터 `접촉단계`, `고객DB승격근거`, `고객DB승격가능`, `타깃리스트반영`, `등급`, `점수`, `다음액션`, `업체명` 순서로 재정렬되고, 색상과 드롭다운이 적용됩니다.

첨부 리서치 브리프 기반 서울·경기 예상 수요 후보를 넣으려면:

```text
CESeL CRM > 서울경기 예상수요 넣기
```

이 기능도 `12_웹크롤링DB`에만 넣습니다. `01_고객DB`에는 넣지 않습니다.

진짜 접촉 대상으로 볼 후보만 `타깃리스트반영` 열에 `Y`를 쓰고 아래 메뉴를 누릅니다.

```text
CESeL CRM > 선택 웹리드 타깃 반영
```

## 4. 타깃리스트에서 접촉 후보 관리

### Step 1. `08_타깃리스트`에 후보 입력

필수로 채우면 좋은 열:

- `업체명`
- `고객유형`
- `지역`
- `우선제품`
- `연락처` 또는 `이메일`
- `출처`
- `메모`
- `시설/자산 단서`
- `예산/투자 단서`
- `의사결정자 단서`

예시:

```text
업체명: AK플라자 분당 / 상품본부
우선제품: AlphaCafe
출처: 공식 홈페이지 / 조직현황
시설/자산 단서: 백화점, 상품본부, Food/F&B팀
예산/투자 단서: 프리미엄 디저트, 팝업, 시즌 SKU
의사결정자 단서: F&B팀 공개
```

### Step 2. 점수화

`CESeL CRM > 타깃리스트 점수화`를 누릅니다.

자동으로 채워지는 열:

- `거래준비도 점수`
- `점수 사유`
- `A/B/C 등급`
- `탈락질문 결과`

등급 의미:

- `A`: 오늘 바로 전화할 후보
- `B`: 공식 출처나 담당자 보강 후 전화할 후보
- `C`: 낮은 우선순위로 저장할 후보
- `보류`: 자산/시설/출처/승인 리스크 때문에 아직 접촉 우선순위에서 제외

### Step 3. 검증완료 후보만 고객DB 반영

`CESeL CRM > 검증완료 고객DB 반영`을 누릅니다.

그러면 `08_타깃리스트`에서 A/B급이면서 `고객DB승격근거`가 아래 중 하나인 후보만 `01_고객DB`로 넘어갑니다. 이미 같은 업체명이 있으면 중복 추가하지 않습니다.

- `회신`
- `오프라인접점`
- `연락처확보`
- `담당자확인`

아직 웹에서 찾기만 한 후보, 온라인 접수만 한 후보, 메일만 보낸 후보는 고객DB로 넘어가지 않습니다.

### Step 4. 전화/메일 후 접촉기록 작성

통화나 메일 후에는 `02_접촉기록`에 결과를 남깁니다.

좋은 기록 예시:

```text
담당자 연결 성공. F&B팀에서 여름 딸기 디저트 SKU 검토 가능.
이번 주 10분 미팅 제안했고 일정 회신 대기.
```

나쁜 기록 예시:

```text
통화함.
```

나중에 접촉 결과를 점수 보정에 쓰려면 “담당자 연결”, “예산 검토”, “미팅 수락”, “시설 없음”, “예산 없음” 같은 판단 단어가 들어가야 합니다.

## 5. Gmail 답장 확인

대표님이 Gmail에서 직접 메일을 보낼 때 제목에 고객ID를 넣습니다.

```text
[C-0007] 프리미엄 딸기 디저트 SKU 관련 10분 미팅 요청
```

그 다음 `CESeL CRM > Gmail 답장 확인`을 누르면 `03_메일링관리`의 회신 여부와 회신일을 업데이트합니다.

자동 이메일 발송은 하지 않습니다. 이 CRM은 답장 추적만 합니다.

## 6. 자동 트리거

`CESeL CRM > 트리거 설치`를 누르면 Gmail 답장 확인이 1시간마다 실행됩니다.

처음에는 수동으로 충분히 테스트한 뒤 설치하는 것을 권장합니다.

## 7. 보류되는 대표 케이스

아래 후보는 점수가 높아 보여도 보류될 수 있습니다.

- 공식 출처 없이 개인 연락처만 있음
- 블로그 댓글, 리뷰, 개인 카카오 ID만 있음
- 가격, ROI, 회수기간, 생산량, 외부자료 발송을 먼저 요청함
- AlphaFarm Core인데 토지만 있고 창고/건물/담보 자산이 없음
- 40ft HC인데 컨테이너/냉방/전력/배수/실증 목적이 확인되지 않음

## 8. 지금 단계에서 아직 자동화하지 않는 것

- Gmail 자동 발송
- 가격표/ROI/생산량 자동 제안
- 비공식 개인정보 크롤링
- Naver/Google/Instagram 무차별 자동 스크래핑

이 네 가지는 영업 리스크와 보안 리스크가 커서 의도적으로 막아둡니다.
